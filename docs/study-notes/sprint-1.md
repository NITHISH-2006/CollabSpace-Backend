# Sprint 1 Study Notes - Database and Secure Connectivity

## db/schema.sql

**Purpose:** Creates the `CollabSpaceDB` database and all five tables with primary keys, foreign keys, defaults, and the required index.

**Key lines explained:**
- `CREATE DATABASE IF NOT EXISTS CollabSpaceDB;` - safe to re-run; it will not fail if the database already exists.
- `USE CollabSpaceDB;` - selects the database so all following statements target it.
- `` `User` `` - backticks quote identifiers. `USER` and `SESSION` are MySQL keywords, so quoting avoids syntax problems.
- `UserID INT AUTO_INCREMENT PRIMARY KEY` - integer primary key generated by MySQL on each insert.
- `Email VARCHAR(100) NOT NULL` + `CONSTRAINT uq_user_email UNIQUE (Email)` - enforces unique emails. This is what makes an invalid duplicate insert fail.
- `OwnerID INT NOT NULL` + `CONSTRAINT fk_document_owner FOREIGN KEY (OwnerID) REFERENCES User(UserID)` - a document must belong to an existing user. This is the one-to-many Document-User relationship.
- `DATETIME(6)` - date and time with microsecond precision. Used for `ConnectedAt`, `LastSeenAt`, and `AppliedAt` so the stale-session sweep and latency tests are accurate.
- `DEFAULT CURRENT_TIMESTAMP(6)` - if no timestamp is supplied, MySQL stores the current moment automatically.
- `Status VARCHAR(20) NOT NULL DEFAULT 'Active'` - sessions default to active if the caller does not specify a status.
- `INDEX idx_document_applied (DocumentID, AppliedAt)` - a composite index that speeds up the most frequent lookup: "operations for a document ordered by time".
- `ENGINE=InnoDB` - required for foreign keys and transactions in MySQL.

**Design decision:** The case study lists `CreatedAt` as `DATE` in one place but describes it as "date and time". We use `DATETIME` so the dashboard can sort documents by recency.

**Likely demo questions:**
- Why use an index on `(DocumentID, AppliedAt)`? Because the app repeatedly reads a document's operations in time order; without the index MySQL scans the whole table.
- What happens if you insert a Document with a non-existent OwnerID? The foreign key rejects it.

## db/seed.sql

**Purpose:** Resets the tables and inserts deterministic sample data: 10 users, 10 documents, 10 sessions, 10 snapshots, and 200 edit operations.

**Key lines explained:**
- `SET FOREIGN_KEY_CHECKS = 0;` - temporarily disables foreign key checks so tables can be truncated in any order.
- `TRUNCATE TABLE ...` - empties a table and resets its AUTO_INCREMENT counter, making re-runs deterministic.
- Explicit `UserID`, `DocumentID`, etc. - we supply the IDs ourselves so the seed data is reproducible and foreign keys are easy to guarantee.
- `SET FOREIGN_KEY_CHECKS = 1;` - re-enables checks immediately after truncation.
- The `EditOperation` insert uses a numbers generator: `ones` (0-9) cross joined with `tens` (0-90) cross joined with `hundreds` (0, 100, 200). This produces `n` from 0 to 299; `WHERE n BETWEEN 1 AND 200` keeps exactly 200 rows.
- `1 + (n % 10)` - maps each operation to a valid DocumentID and SessionID between 1 and 10, so every row satisfies its foreign keys.
- `CASE WHEN n % 2 = 0 THEN 'INSERT' ELSE 'DELETE' END` - alternates operation types, giving both types for analytics tests.

## db/constraint-tests.sql

**Purpose:** Proves the schema accepts valid data and rejects invalid data.

**Expected results:**
- T1 duplicate email -> error 1062 (unique violation).
- T2 NULL LastName -> error 1048 (column cannot be null).
- T3 OwnerID 9999 -> error 1452 (foreign key constraint fails).
- T4 default status -> succeeds, and the SELECT shows `Active`.
- T5 SessionID 9999 -> error 1452 (foreign key constraint fails).

## src/main/java/com/collabspace/util/PropertyUtil.java

**Purpose:** Reads `db.properties` from the classpath and builds the JDBC URL. No credentials live in Java source.

**Key lines explained:**
- `private static final Properties PROPERTIES = new Properties();` - one shared key/value store for the whole application.
- `static { ... }` - a static initializer runs once when the class is first loaded, before any method call.
- `PropertyUtil.class.getClassLoader().getResourceAsStream("db.properties")` - finds the file in `src/main/resources`, which Maven copies to `target/classes`.
- `if (input == null) throw ...` - fails fast with a clear message if the file is missing.
- `PROPERTIES.load(input)` - parses the key=value file.
- `try (InputStream input = ...) { }` - try-with-resources closes the stream automatically.
- `return "jdbc:mysql://" + host + ":" + port + "/" + database + "?..."` - builds the connection string. `allowPublicKeyRetrieval=true` and `useSSL=false` let a local MySQL 8.x server using `caching_sha2_password` authenticate over a non-TLS local connection.
- `private PropertyUtil() { }` - prevents instantiation; this is a utility class.

## src/main/java/com/collabspace/util/DBConnection.java

**Purpose:** Provides one shared JDBC connection, created from the values in `PropertyUtil`.

**Key lines explained:**
- `private static Connection connection = null;` - the case study requires a static connection variable.
- `public static synchronized Connection getConnection()` - `synchronized` prevents two threads from creating two connections at the same time.
- `if (connection == null || connection.isClosed())` - creates a connection only when there is none or the old one was closed.
- `DriverManager.getConnection(url, user, password)` - the actual JDBC call to MySQL.
- `closeConnection()` - closes the connection and resets the field to `null`.

**Important:** A single shared `Connection` is not safe for concurrent writes. The pipeline will send all database writes through one consumer thread, so only one thread uses the connection at a time.
